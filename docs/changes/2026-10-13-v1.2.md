# 1.2 增量计划：系统声音与独立音量

## 范围与验收

用户要求接入系统声音。本次使用 Windows 的系统输出回环，捕获整台电脑的播放声音，包括选中软件之外的应用。增加可选系统声音、系统声音 / 麦克风各自 0–100% 音量，支持无声音、系统声音、麦克风、两者混合四种组合。默认关闭系统声音，旧配置补齐两个 100% 音量，不改变旧版的启动选择。

只请求已选本地广播窗口的屏幕 / 窗口捕获；用户启用系统声音后才允许 Electron `audio: 'loopback'`。不使用 `loopbackWithMute`，不改变 Windows 扬声器音量，不安装驱动或另开原生回环进程。采集失败或缺少系统音轨时显示明确错误，释放资源，不声称视频启动等于系统声音可用。

系统声音和麦克风通过一个由捕获会话拥有的 AudioContext 混成一条发送音轨。分别用 GainNode 调节广播音量，音量在广播时可改；麦克风静音不影响系统声音。预览保持静音，接收方保留自己的静音和音量控制。停止、准备取消、切换画面、迟到设备请求、AudioContext 启动失败、窗口重载 / 关闭都释放原始轨道、混合输出和音频上下文。

1.1.1 的 UPnP 修复合并到此次 1.2.0 交付，不额外发布未验证的中间便携版本。真实中兴路由器已通过 1.1.1 源码 / GUI 成功读到 WAN；最终产物仍须以 1.2.0 重新核对。保持 HEVC / 回落、原保存字段、带宽预算、邀请与浏览器观看、默认 TCP / UDP 端口及只读路由发现边界。

## 共享契约与文件归属

配置字段固定为 `systemAudio: boolean = false`、`systemVolume: integer 0..100 = 100`、`micVolume: integer 0..100 = 100`。布尔与数值在主进程统一验证；旧设置缺字段正常补默认，畸形值拒绝，不保存临时采集 ID。

`createAudioMixer({capture, displayStream, microphoneStream = null, systemAudio = false, systemVolume = 100, micVolume = 100, AudioContextCtor, MediaStreamCtor})` 为异步工厂，位于 `src/renderer/audio-mixer.mjs`；返回 `{stream, setSystemVolume(value), setMicrophoneVolume(value), setMicrophoneMuted(value), dispose()}`。`capture` 是现有 CaptureSession，原始 / 输出轨道与上下文在首个 await 前登记所有权，取消期间不等待 resume 完成。无输入不创建音频上下文；启用系统声音但缺少其音轨明确失败；最终流保留原视频轨道且最多一条音频轨道。dispose 幂等，不释放其他会话资源。根负责在生产 GUI 安装和保存音量设置，并让麦克风静音只调用 mixer 的麦克风接口。

UI IDs 固定为 `system-audio`、`system-volume`、`mic-volume`，对应百分比输出 `system-volume-value` / `mic-volume-value`；现有 `mute` 为麦克风静音。预览 `preview` 静音；`system-volume` 和 `mic-volume` 在对应声音启用时可操作，广播中可实时调节。

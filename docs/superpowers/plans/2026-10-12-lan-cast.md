# LAN Screen Cast 实施与集成计划

设计合同见 [软件设计](../specs/2026-10-12-lan-cast-design.md)。用户授权先完成结构设计，再使用 subagent 并行开发；由主代理统一集成与打包。无需重建已有基础模块，针对当前实现补足生命周期、二级 NAT 和便捷导入。

## 工作基线

- Windows，Electron 44.7.0、ws 8.22.0、qrcode 1.5.4，原生 HTML / CSS / JS。
- 已实现捕获、GUI、HTTP / WS、邀请与 5 路 WebRTC；已有 Node 配置、服务和启动取消测试。
- 规划时 smoke 已覆盖屏幕、窗口和同机五路视频；音频断言尚未通过。实施后已解决，完整证据见验证记录。
- 目录当前不是 Git 仓库；共享工作目录内按文件所有权并行，禁止覆盖其他模块或修改系统路由器 / 防火墙。
- 默认 100 Mbps、1080p30、6 Mbps × 5，预算上限 70 Mbps；TCP 8765，UDP 50000–50100。

修改合同或依赖其他所有者的文件前先通知主代理。子代理仅运行其单元 / Node 集成测试，不同时启动桌面 smoke。主代理串行运行所有桌面测试，避免采集、端口和 Electron 进程互相干扰。新 helper 文件必须给出责任、接口和测试，不能只包装已有实现。

## 依赖顺序

1. 设计冻结字段及共享模块接口，随后派发三个模块。
2. 网络子代理提供 `network.mjs` 与 SessionInfo；广播端按该接口接入；主代理按固定 ShareController 合同实现 UI，不需互改。
3. 子代理各自提交文件变更说明、命令与实际测试输出；主代理检查所有结果并处理合同偏差。
4. 完整 Node 测试与语法检查通过后，运行源码桌面 smoke 和生命周期回归。
5. 独立审查新模块、修复必要问题，重跑受影响验证。
6. 从最终源码构建便携目录 / EXE，运行打包版本 smoke，检查资源与压缩包，再写验证记录。

## 模块验收

- [x] 网络：普通 LAN 行为保持，一级 WAN IPv4 和 TCP 端口被严格校验，内外两种邀请同一次认证。
- [x] 网络：映射地址的 Host / Origin 允许，其他 Origin 拒绝；停止回收浏览器预连接，不复活已取消服务器。
- [x] 网络：映射 UDP 候选保留原候选、保持端口、仅作用于匹配网卡与范围；SDP 和 trickle 一致。
- [x] 广播：屏幕结束发生在麦克风请求、服务启动或保存设置期间都能取消；迟到轨道不泄漏。
- [x] 广播：所有协商异步回调核对当前 peer / generation；队列与超时有界，失败释放观看人数。
- [x] 接收：首次容量满提示，恢复中容量满继续退避；移除、广播结束和用户断开停止重试。
- [x] 接收：更换邀请 URL 不沿用旧令牌；播放器音频恢复明确，统计不误称端到端延迟。
- [x] 便捷观看：二维码 / 复制 / 地址导入和 `.url` 文件均有可复核结果。

## 失败处理

测试失败先保存同次诊断与最小复现，再修实现或错误的验证方法。实际音视频必须以解码帧 / 音频样本证据为准，不能仅以连接状态通过替代。若 Electron 被开发沙箱的 AppContainer ACL 阻止，使用普通交互 Windows 会话运行测试，保留应用 sandbox 配置。真实校园网络无法自动验证时保留明确未测项，不阻止交付已验证的程序。

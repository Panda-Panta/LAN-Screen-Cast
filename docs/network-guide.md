# 校园网、二级路由器与观看入口

假设广播电脑 LAN 地址是 `192.168.31.146`，二级路由器的 WAN 地址是 `10.20.30.40`，软件本地网页端口是 `8765`。这些只是说明用地址，请用你实际的路由器信息。

```text
一级校园网络：观看者 ──→ 二级路由器 WAN 10.20.30.40
                             │ TCP / UDP 端口转发
二级路由器内网：          广播电脑 192.168.31.146
```

## 路由器设置

1. 在 DHCP / 静态租约中固定广播电脑的 LAN 地址。
2. “虚拟服务器”“端口转发”或“端口映射”通常是同一类设置，添加：

| 协议 | 外部端口 | 内部目标 IP | 内部端口 |
| --- | --- | --- | --- |
| TCP | 8765 | 192.168.31.146 | 8765 |
| UDP | 50000–50100 | 192.168.31.146 | 50000–50100 |
| TCP（RTMP） | 1935 | 192.168.31.146 | 1935 |

3. UDP 需要相同范围。如果路由器用“起始端口 + 结束端口”，分别填写 50000 和 50100；若只能逐端口添加，可以在软件中选择至少 32 个端口的较小范围并逐一映射。例如 50000–50031，但两边必须一致。
4. WAN TCP 可以换成另一个未占用端口，例如外部 18765 → 内部 8765。软件的“路由器对外网页端口”填 18765，普通“网页端口”仍为 8765。
5. 在软件中选择电脑的真实 LAN 网卡，打开“一级网络用户观看”。自动模式会向该网卡默认网关查询路由器 WAN 地址；需要路由器响应 UPnP IGD 或 NAT-PMP 的地址读取接口。若不支持，关闭自动模式并手动填 10.20.30.40。开始后一级用户打开 `http://10.20.30.40:8765/` 或包含令牌的邀请。二级内网用户打开本地分享入口。

RTMP 的画面和声音共用一个 TCP 端口，默认 1935；“路由器对外 RTMP 端口”可不同，例如外部 11935 → 内部 1935。只看 RTMP 可仅转发该 TCP 端口，网页观看仍需要网页 TCP 和 WebRTC UDP；两种方式都使用时配置三组。

WAN 地址可能随校园网租约变化。自动模式每 30 秒检查，刷新当前广播的网页 / RTMP 地址、二维码、服务允许地址和后续连接候选；需把新邀请重新分享，旧链接不自动跳转。手动模式需要同步更新后重新广播。软件只读地址，不创建映射，也不改变 DHCP。电脑的默认网关地址与路由器 WAN 地址不同。Windows 防火墙按这台电脑实际的网络类型允许应用及上述端口，端口映射不会自动创建防火墙规则。RTMP 原生服务随软件提供，Windows 防火墙若按程序规则放行，需要允许此程序和 `resources/media/bin/mediamtx.exe` 对应监听端口。

TCP 网页端口承载页面与连接信令；画面和声音通过单独的 WebRTC UDP 媒体通道传输。UDP 范围由 Electron 分配连接时使用的本地端口，覆盖连接分配与重连。默认 50000–50100 是 101 个端口，并非必须开放 50000–51000；软件支持缩小到 50000–50031。范围里的端口不会全部持续发送流量，范围大小本身不增加带宽消耗。只转发网页 TCP 端口不能作为 WebRTC 媒体可达的依据。关于信令与媒体通道，见 [WebRTC 连接说明](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Connectivity)。

若路由器 UPnP 已开启而仍提示“默认网关未响应”，检查所选网卡、默认网关及路由器的 UPnP 设置。正式 Release 1.0 已包含内部测试阶段修复的解析兼容性：支持标准空 `EXT:` 字段和带点号的 UPnP 1.1 字段名。软件保留只读地址查询；开启 UPnP 后仍需设置上述端口转发。

## 逐步判断连接问题

| 接收方实际现象 | 已确认环节 | 下一步 |
| --- | --- | --- |
| 无法打开网页 | 尚未证明 TCP 可达 | 检查广播、WAN 地址、TCP 转发、Windows 防火墙、校园网络隔离 |
| 网页打开，认证被拒绝 | 页面 TCP 可达 | 使用本次广播邀请或当前观看码 |
| 已加入，媒体协商失败 | 页面和信令可达 | 检查 UDP 同端口映射、UDP 防火墙、上级 ACL / 用户隔离 |
| 连接建立，尚未出现画面 | 媒体连接建立，但未确认视频帧 | 等待首帧；查看源是否关闭 / 最小化，检查发送端负载 |
| 已收到画面，声音未播放 | 视频帧已收到 | 点击开启声音，检查发送方对应声音开关 / 音量、Windows 输出设备及双方静音状态 |
| 画面卡顿 | 链路可用 | 降到 720p / 30 fps，减少观看人数，检查真实带宽和电脑负载 |

这些判断以接收方实际状态为准，不把发送端自测或 HTTP 页面打开当作完整音视频成功。若校园网络禁止其他用户访问你的路由器 WAN 或禁止 UDP，需要网络管理方允许相应通信；当前软件没有中继服务器，不能自动绕过这种限制。

## 网页和 RTMP 观看地址

开始广播后选正确分享入口，可复制网页邀请、扫码，或复制 RTMP 地址到 PotPlayer / VLC。PotPlayer 使用“打开链接”（通常 Ctrl+U），VLC 使用网络串流入口。网页的地址导入入口可用于换到另一条邀请，直接复制地址即可分享。

网页邀请 / 二维码含当前会话的邀请凭据，RTMP 地址也含随机会话路径，持有地址即可观看。广播停止后失效；重新开始时需重新分享。打开网页后点击开始观看以满足浏览器的音频播放策略。

正式版 RTMP 默认 HEVC / AAC + NVIDIA 硬件优先，保留已保存偏好；HEVC 使用 Enhanced RTMP，接收端也需要支持扩展。需要播放器兼容性时手动选择 H.264。编码器由每次启动的真实短帧编码探测选择，首先尝试 NVENC；硬件不可用时，auto 可尝试同编码的软件模式，hardware 则报错并保留网页广播。播放器网络缓存可能增加播放延迟，可以在接收端减少缓存。本机 FFmpeg 能解码不等于某一版本 PotPlayer / VLC 已经兼容 HEVC RTMP，现场结果要分别记录。

## 实现边界

静态 UDP 映射补充的是 WebRTC 的 ICE 地址候选，实际 ICE 检查才决定媒体路径能否使用。需要一一对应的端口、可用的数字 IPv4 和允许通信的网络。保留内网候选以便同路由器用户观看，不强制所有人经过 WAN。相关原理见 [ICE / NAT RFC 8445](https://www.rfc-editor.org/rfc/rfc8445)；发送端范围由 [Electron setWebRTCUDPPortRange](https://www.electronjs.org/docs/latest/api/web-contents/) 设置。

真实二级路由器和一级校园用户尚需现场验证，不能用本机浏览器模拟结果代替。
